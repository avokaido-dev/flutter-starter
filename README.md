# Flutter Starter

Frontend scaffold generated by Avokaido.

This is the **UI layer only** — screens, navigation, theme, and stub
data services. The Avokaido batch runner wires up real Firebase
(Auth + Firestore + Hosting/App Hosting), replaces the stubs in
`lib/services/`, and lands the deploy workflows in a follow-up pass.

## Run it

```bash
flutter pub get
flutter run
```

The app boots into the placeholder home screen. Tap through the
generated screens — every gesture works against the stub services
(no network, no auth).

## Project structure

```
lib/
  app.dart                 MaterialApp.router
  main.dart                runApp(MyApp())
  router/
    app_router.dart        GoRouter wired to routes.dart
    routes.dart            Route table (regenerated per app)
  theme/
    app_theme.dart         Material 3 theme builder
    brand.dart             Per-app palette + font
  services/
    auth_service.dart      Stub — TODO(avokaido): wire Firebase
    api_client.dart        Stub — TODO(avokaido): wire backend
  widgets/                 Shared UI atoms
  screens/                 App-specific screens
  models/                  App-specific data models
```

## What the batch runner does next

Search the codebase for `TODO(avokaido):` markers. Each one is a
single, focused change: swap a stub for the real thing, add a missing
Firestore index, push a deploy workflow. The markers carry the exact
contract (collection names, return types) so the runner doesn't have
to infer what you meant.
